# 全量生成器（队友 model_v2）评估结论

日期：2026-09-10　对应方案条目：§7 前置、以及"NIR 是否值得部署"的数据基础。

## 1. 一句话结论
**不要用队友的全量生成器替换我们当前的冻结生成器。** 在同一批 327 张测试样本、同一目标口径下，
我们的生成器 **22.84 dB / SSIM 0.837**，他们的 **14.25 dB / SSIM 0.622**（差 8.6 dB）。
最可能的原因是**他们的 NIR 目标与 RGB 朝向相差 90°**（数据准备问题），而不是"全量数据没用"。

## 2. 评估设置（同口径）
| 项 | 内容 |
|---|---|
| 测试样本 | 队友清洗后全量 HSIFoodIngr-64 的 **test 划分 327 张**（`model_v2/data/HSIFoodIngr-64/test/*.h5`，19 个 h5） |
| 读取方式 | base(anaconda3, 有 h5py) 导出为原生 dtype npy → `artifacts/hsi_v2_test/`（rgb uint8、nir uint16） |
| 目标口径 | 统一到**我们的固定缩放 [0,1] NIR**：`our_nir = 4.0411e−05 × their_u16(rot90×3) − 0.11354`（144 张重叠扫描标定，**残差 0.0054、R²=0.9990**，934 万像素） |
| 指标 | 逐图 PSNR `10·log10(1/MSE)`、批 MSE 口径 PSNR、SSIM（range=1，gaussian 11×11）；两模型同一实现 |
| 模型 A | 队友 `model_v2/checkpoints/generator/best_model.pt`（UNet 6-down，base 64，**训练 565 轮**，训练样本 2772） |
| 模型 B | 我们 `checkpoints/hsi_unet_v2/best.pt`（UNetGenerator 4-down，base 64，**训练 96 轮**，训练样本 144） |
| 证据 | `artifacts/generator-aligned-comparison.json`、`artifacts/v2_nir_calibration_rot.json` |

## 3. 结果
| 模型 | PSNR（逐图均值） | PSNR（批 MSE） | SSIM |
|---|---|---|---|
| 队友全量（对齐后） | **14.25** | 12.47 | **0.622** |
| 我们（144 扫描） | **22.84** | 22.01 | **0.837** |

交叉校验：我们的生成器在自己 33 张测试集上是 23.33 dB / 0.812，在这 327 张上是 22.84 dB / 0.837
→ 数值一致，说明评估链路可信（论文参考值 30.61 dB / 0.865，口径不同，仅作背景）。

## 4. 为什么会有这个结果（已定位）
1. **两边 RGB 完全一致**（corr = 1.0000，同朝向、同 PNG 来源）；
2. **他们的 NIR 与我们相差 `rot90×3`**（corr = 0.9993）→ 队友管线里 NIR 与 RGB **朝向不一致**；
3. 我们的管线在准备数据时把原生 HSI **顺时针旋转 90° 与 PNG 对齐**（见 `data/hsi_prepared_v2/manifest.json` 的 `orientation` 字段），
   所以我们的生成器学的是"RGB→同朝向 NIR"，而他们的生成器被迫学"RGB→旋转 90° 的 NIR"，实际重建质量明显更差；
4. 未对齐时更差（各候选口径 7.9–15.0 dB），这也解释了此前"同一个模型换口径就崩"的现象。

**给队友的具体修复建议**：把 h5 里的 `nir` 与其 `rgb` 对齐（我们这边的做法是 `np.rot90(nir, 3)`，
即把原生 HSI 顺时针 90°），然后重训生成器与多任务模型（他们 16 类的 4 通道多任务同样存在该问题）。

## 5. 对"是否值得上 NIR"的影响
- 现有 144 扫描生成器（22.84 dB）已明显好于队友那版，但它仍是**小数据**训练出来的；
- 真正可能接近论文口径的路径是：**用全量 2772 训练样本 + 正确朝向/口径重训我们的生成器**；
  代价明显（每 epoch 约 30 倍计算量，全量 100 轮不现实；需按预算压到 20–30 轮或加大 batch 并行），
  建议作为**单独排期的长任务**（例如夜间 8h 预算内跑 20 轮，用验证 PSNR 早停）。
- 在拿到该结果之前，NIR 臂的结论按"小数据生成器"口径陈述，不外推到论文水平。

## 6. 边界
- 队友的 `data/hsifoodingr_loader.py` 未入库，其**原始**归一化口径仍未知；本文用的是"数据侧标定 + 朝向对齐"得到的等价口径（R²=0.999），
  因此结论"他们的生成器更差"是稳健的（同口径下差 8.6 dB），但**不是**对其代码的直接复现评估。
- 队友 16 类多任务权重（`model_v2/checkpoints/multitask`）**未接入**我们的应用：类别体系（16 类 vs 11/12 类）、
  目标与损失定义均不同，只能作参考对照。
