# 标签版本核对（整改清单 第4节）

> 结论：**规则修复 ≠ 已有训练标签更新 ≠ 已训练权重吸收修复。**
> 现状：`build_categories.py` 的标签规则已修复（词边界/右端最长/人工覆盖），但**当前五目标 manifest 与训练仍使用旧标签**。

## 1. 规则已修复（代码层）
- `src/data/build_categories.py`：`classify_ingredient` 已由裸子串改为词边界 + 右端/最长短语 + OVERRIDES。
- 回归测试 `tests/test_build_categories.py` 5/5 通过；文档 §4.2 四个错例已修（apple pie→dessert、eggplant→vegetable、graham cracker→grain、cream of mushroom soup→soup_stew）。

## 2. 规则修复产生的标签差异（真实数据审计）
- `scripts/audit_category_labels.py`（数据 `data/Nutrition5k/dish_ingredients.csv`）：5006 餐盘 / 249 食材 → **6 种食材、82 道餐盘（1.6%）** 的旧/新标签不同（多为真修正：eggplant→vegetable、watermelon/果汁不再误标 vegetable、chicken/tuna/pasta salad 按"头名词 salad"归 vegetable）。

## 3. 关键事实：新标签尚未进入 manifest 与训练
- `src/data/meal_macros_manifest.py` 从**冻结 manifest** 复制 `category/category_idx`（旧标签），并未按新规则重算。
- 因此 `results/meal_macros_v1/manifest.json`、`meal_macros_expanded_v1/manifest.json` 及由此训练的 `v1` / `v1_expanded` 模型，**类别标签仍是旧规则产物**。
- **不能宣称"蔬菜偏置已解决"**；当前五头模型的分类头仍受旧标签分布影响（vegetable 训练占 ~54%）。

## 4. 要做到"修正生效"，需（下一阶段）
1. 用新规则对 `dish_ingredients.csv` 重算每道菜的 `category`（复用 `build_categories.classify_ingredient` + 40% 阈值/mixed 规则），生成**新版本清单**（`meal_macros_v1_corrected`），记录 `category_source`/规则版本/SHA，不覆盖旧冻结 manifest。
2. 语义问题（水果/蔬菜、菜名 vs 主要食材组）需**升级 label_schema** 决策后再定（涉及类别集合变化）。
3. 用新清单**重新训练**五头/消融模型，再与旧模型对照；旧模型保留作对照。
4. 训练/验证各类别支持数需公开；无验证样本类别不得宣称已完成验收。

从某个被修正餐盘（如 "eggplant" 相关）出发：修正规则 → 新标签 → 新 manifest（SHA）→ 训练配置（记 manifest SHA）→ 权重 → 与旧模型比。**当前未达成，属待办。**
