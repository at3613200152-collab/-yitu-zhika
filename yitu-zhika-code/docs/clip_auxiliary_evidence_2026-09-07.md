# CLIP 辅助与下一轮消融：证据和建议

日期：2026-09-07。本文为调研建议，不代表功能已实现或训练效果已验证。

## 一手证据

- CLIP 通过图文对比学习获得视觉与文本表示，并能将文本描述作为零样本分类候选；这不是克数或烹饪油量的测量模型。[CLIP 原论文](https://proceedings.mlr.press/v139/radford21a.html)
- 官方接口提供 `encode_image`、`encode_text`；零样本例子比较归一化图文特征，并对候选集相似度做 softmax；另有冻结图像特征加线性分类器的范例。候选相对分数不应未经校准就写成“识别正确概率”。[官方代码与例子](https://github.com/openai/CLIP)
- CLIP 官方模型卡提醒：类别集合会影响表现，细粒度分类存在局限，需要任务内测试；原版并未专门训练和评估非英语语言。中文界面可映射到经人工核对的英文类别提示词。[模型卡](https://github.com/openai/CLIP/blob/main/model-card.md)
- Nutrition5k 提供餐盘/食材质量、营养标签、侧视视频和部分顶视 RGB-D；官方字段没有完整结构化的烹饪方式真值。官方划分将同一餐盘的递增扫描保留在相同 split。[官方数据说明](https://github.com/google-research-datasets/Nutrition5k)
- Nutrition5k 原论文 §4.3–4.4 已研究每克营养回归、独立质量估计及组合，故“质量×能量密度”本身不能宣称首次提出。§4.1 的百分比是 MAE/标签均值，不是逐样本 MAPE。[原论文](https://arxiv.org/html/2103.03375v1)
- 学习门控以调节模态贡献已有先例；并不保证对本项目生成 NIR 有效。[Gated Multimodal Units](https://arxiv.org/abs/1702.01992)
- 一致性正则化已有既有研究；本项目同餐盘跨视角监督是具体适配，不能因采用一致性损失就声称全新算法。[Mean Teacher](https://arxiv.org/abs/1703.01780)

## 建议实现（待实验验证）

1. **CLIP 先做辅助特征，不覆盖真标签。** 冻结原始通用 CLIP，以同一训练图像生成归一化视觉特征，经小投影层辅助类别/能量密度头。独立开关控制是否参与推断。UI 可显示候选类别和“语义相似度”；不同模型分歧触发用户确认。伪标签如需尝试，应另立实验，只在训练集产生，保留来源和置信度，不写回权威标签。混合餐不能依靠单一菜名查表得到真实热量。
2. **NIR 门控要可关闭、可干预。** 建议 RGB 主干加 NIR 残差分支，`h = h_rgb + sigmoid(g(...)) * h_nir`，保持 RGB 独立通路。门控是学习到的使用系数，不是“光谱可靠性概率”。验证时除直接拼接对照，还测固定门控、强制关闭、置乱/噪声 NIR；记录门控分布、各热量分组误差及额外延迟。预测 NIR 来自 RGB，不是新增实测传感信息。
3. **明确监督质量与能量密度。** 只对质量有效且大于零的真实标签计算 `density = calories / mass`，单位 kcal/g；分别监督质量、密度及其乘积的总热量，避免只监督乘积造成两项任意相互抵消。非负输出、缺失标签掩码、损失缩放均须写入协议。食材标签来自可靠记录；烹饪方式未知则保留未知，不能用 CLIP 猜测补成真值。用户输入油量属于用户声明，不能冒充照片测量。
4. **跨视角一致性不可取代监督。** 仅对同一 `dish_id`、同一次扫描的不同帧配对；不同递增扫描营养量不同，不能当成相同目标。建议先平均两视图真实标签监督，再加较小的标准化预测差损失；无第二视图时掩码。每轮按餐盘采样，不能让多帧餐盘获得三倍独立样本权重。旋转视频帧只能证明有限视角变化；光照/背景泛化仍需独立场景数据验证。

## 可归因的实验顺序

- 保留旧版权重/manifest。新版基线固定同一数据、标签修订、划分、训练预算和预处理。
- 数据扩充本身单独对照：原训练集 vs 加入 128 餐盘；新增侧视图不得混入验证/测试餐盘或同一递增扫描组。
- 在同一新版基线上分别只加：NIR 门控、质量密度因子化、跨视角一致性、CLIP 辅助。之后再跑组合和去除单项的消融；不要只用一条累加链宣称每项独立贡献。
- 固定验证集选择 checkpoint/损失权重/提示词/阈值；测试集不调参。至少报告多种随机种子、配对误差及区间。MAE、RMSE、MAPE 和 MAE/标签均值分别命名；低热量分组如实报告，不删除难例美化分数。
- 已纳入训练的 128 餐盘只能做训练一致性诊断，不能再当未见场景泛化测试。独立侧视测试集应来自冻结测试餐盘或额外保留组，记录拍摄域及来源。

## 与当前 CalorieCLIP 风格基线的区别

本地 `results/calorieclip_official_v1/protocol.json` 已核对：通用 ViT-B/32 初始化、末两层视觉 Transformer 可训练、512/256/64 MLP，只输出 kcal；当前匹配实验不含新增 128 餐盘，且不是作者完整训练复现。本轮提议的 CLIP 语义辅助是额外冻结分支/候选分类，不是将该热量基线改名为分类器。应保留外部热量基线独立成绩与权重；语义文本比较优先用原始通用 CLIP，不默认假定已为回归微调的视觉编码器仍保持原图文对齐。

## 最小验证清单

- 同餐盘/递增组跨 split 泄漏检查；训练标签统计不读测试集；CLIP 缓存绑定模型、图像与预处理哈希。
- 门控关闭时输出等价于 RGB 路径；未知烹饪标签不贡献监督；质量为零不发生除零；因子输出单位与乘积正确。
- 两视图交换顺序不改变一致性损失；相同视图差为零；餐盘采样权重不随帧数增加。
- CLIP 未加载时明确标注不可用，不能显示随机或伪造分类；新增模块不能悄悄替换已审计 Demo 模型。
