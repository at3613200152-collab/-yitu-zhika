# 训练集扩容：类别、重量与烹饪方式的标签证据

核验日期：2026-09-06。范围：一手资料核验与设计建议；没有下载大数据、修改训练代码或启动训练。

## 已核实的标签能力

| 数据来源 | 可以直接支持的监督 | 不能据此声称已有的监督 |
| --- | --- | --- |
| Nutrition5k | 餐盘总重量、热量与宏量营养；配料 ID、名称、克重与营养；多视角 RGB，部分餐盘有原始深度 | 公开元数据 schema 没有独立、完整的烹饪方式字段；配料列表不等于像素级分割标签 |
| Food-101 | 101 个菜品类别、101,000 张图像；每类 750 张训练图和 250 张测试图 | 官方发布说明没有逐图实测克重/热量，不能把“某菜平均一份”变成该照片的重量真值 |

Nutrition5k 字段、拆分及深度格式依据：[官方仓库](https://github.com/google-research-datasets/Nutrition5k)。Food-101 类别与图像规模依据：[ETH 官方页面](https://data.vision.ee.ethz.ch/cvl/datasets_extra/food-101/)。Food-101 训练集有未清洗噪声，不能直接把全部标签视为人工精校。

Nutrition5k 的重量来自逐项加菜时的称量；营养标签由已知配方/配料每克营养与增量重量计算，而非每盘食物都做化学热量测定。原论文也说明了照片遮挡和采集场景地域偏差。其真实深度辅助份量估计有效，但这不能推出普通手机照片或预测 NIR 已具备真实深度测量能力。[原论文 §3.4–3.6、§4.4](https://arxiv.org/html/2103.03375v1)

## 烹饪方式为什么不能只靠增加类别解决

USDA 的 cooking yield 研究明确区分烹饪中的水分流失、吸水、脂肪增加或流失，并使用烹饪前后重量计算产出率。相同原料经不同做法后，熟重与每 100 g 营养含量会改变；不能给“炒”“炸”统一乘一个常数，也不能把生重对应的营养密度直接配给熟重。[USDA Cooking Yields Release 2，pp.3–5](https://www.ars.usda.gov/ARSUserFiles/80400535/Data/retn/USDA_CookingYields_MeatPoultry02.pdf)

直接核算营养保留需要烹饪前后重量与营养组成；若追踪完整去向，还涉及滴液、弃汤等损失。油炸可能同时失水和吸脂，因此“锅里加了多少油”并不等于“这一份最终吃进多少油”。[USDA 研究：Comparisons of Methods for Calculating Retentions of Nutrients in Cooked Foods](https://www.ars.usda.gov/ARSUserFiles/80400525/Data/Classics/retn_murphy.pdf)

## 针对本项目的建议（设计推论，尚未实施）

1. **按标签任务扩容。** 有类别无克重的图像仅用于分类/表征预训练；有真实称重的图像才进入重量监督；做法未知时保留 unknown 并屏蔽该损失。不要把缺失标签当 0，不要给分类图附上推测的“真实热量”。
2. **先利用现有配料监督。** Nutrition5k 配料列表适合探索多标签配料识别，而不是强行压成单一粗类别。逐菜重量还需可对应菜块的区域/实例标签，不能仅凭整盘克重拆分出真值。
3. **补采小规模高质量中餐校准集。** 同一原料或菜品覆盖蒸、煮、炒、煎/炸等实际相关做法，记录可食熟重、配方、实际用油/弃油记录、酱料、生熟状态和多角度照片；不同份量、餐盘与光照要有覆盖。做法允许多步骤或未知，不强制互斥单标签。
4. **重量与能量密度分开检查。** 可比较直接总热量回归与“估计熟重 × 条件能量密度”分解模型。后者只是候选方案，不保证优于现有模型；油脂若已计入熟食密度，不能再次叠加。
5. **产品保留可校正入口。** 单图没有尺度、隐藏酱料或油量不可见时，询问餐具尺寸/份量、烹饪方式和油量档位，或允许用户改克重。预测 NIR 是 RGB 的学习变换，不能声称它测到了照片中不存在的隐藏油量信息。
6. **验证按真实餐盘/批次分组。** 同盘不同视角不算独立新样本；保持固定测试集，分别报告类别、份量区间和做法子组误差。新增拍摄域单独留出手机场景测试，防止只在固定扫描设备上表现良好。

本文件的模型、采集与界面建议是基于上述标签边界的工程推论，不是来源已经证明的项目效果。
