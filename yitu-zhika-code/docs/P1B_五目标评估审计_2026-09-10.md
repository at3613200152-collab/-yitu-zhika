## 三、样本数 16136 根因定位
- `v1` 的 `test_metrics.json` 上报 `n=16136`，但逐目标有效样本均为 507、CSV 也是 507。
- **根因**：`train_meal_macros.py` 的 `epoch_pass` 里 `size = len(ids) if ids else len(dish_ids)`，把**已累计的 ids 长度**当批大小，导致 `n` 与 `reg_total` 的加权都被**累计长度**污染 → N 巨大、归一化 L1 被错误加权的"累计方差"。
- **已修复**：`size = len(dish_ids)`（当前批大小）。**v1_expanded 用的是修复版**（其 `test_metrics.json` `n=507` 正确）；`v1` 是修复前产物，仅记录性 bug，**逐字段指标不受影响**（逐字段按全部有效样本算，非按该 n 加权）。
- 影响：`v1` 的**验证选模（best_epoch/reg_normalized_l1）**可能被该加权 bug 影响 → **不建议将 v1 作为上线/选模依据**；`v1_expanded` 选模正确。

## 四、选模正确性
- 在线/对照目前使用 **v1_expanded**（修复版）：`best_epoch=29`（验证归一化 L1 最小），测试 507 一次性最终评估；其选模基于**修复后的 val reg_normalized_l1**，正确。
- 规则：用验证集选模；507 测试仅最终评估一次，不反复挑。
