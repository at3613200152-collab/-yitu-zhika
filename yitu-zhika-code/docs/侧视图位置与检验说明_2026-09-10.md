# Nutrition5k 侧视图：位置、数量与"能不能用来检验模型"

日期：2026-09-10　用途：回答"侧视图在哪、怎么自己检验模型"，并说清**哪部分算泄漏**。

## 1. 位置（都在 D 盘，不在仓库内）

| 集合 | 路径 | 内容 |
|---|---|---|
| 主集合 | `D:\yitu-data\Nutrition5k\side_angle_expansion_v1\<dish_id>\` | **124 道菜 × 3 帧**：`frame_0000.png`、`frame_0030.png`、`frame_0060.png`（另有 `camera_A.h264` 视频、`decoded_frames.json`）；实测该目录下 PNG **373 个**（其中 372 个被索引引用，1 个为多余解码帧） |

| 清单 | `yitu-zhika-code/data/side_angle_manifest/manifest.json` | 128 道菜的 `dish_id / category / targets / frames[]`（含逐帧路径与 md5），`split_counts={'train': 128}` |
| **索引表（我方生成）** | `yitu-zhika-code/results/side_angle_index.csv` | 128 行：`dish_id / category / 真值(热量·重量·蛋白·碳水·脂肪) / 训练用图 / pilot 3 帧路径 / expansion 3 帧路径`。生成脚本 `scripts/build_side_angle_index.py` |

合计：**128 道菜 = 124（expansion）+ 4（pilot）**，每菜 3 帧（帧号 0000 / 0030 / 0060）。

## 2. ⚠️ 关键：这批侧视图**进过训练**（必须按帧分层读结果）

实测（`results/meal_macros_expanded_v1/manifest.json`）：
- 3390 行里有 **128 行带 `views`**；这 128 行的 **`image`（训练时唯一被读入的图）就是侧视帧**，
  且**一律取 `frame_0000.png`**；它们的 `split` **全部是 `train`**；
- 这 128 道菜**都不在冻结 base 3262 清单内**（即它们就是 P1-C 里说的"新增 128 餐盘"，实际是**侧视视角补充**，
  不是俯拍新盘）；
- 五目标加载器每行只读一张图（无多视角融合、无帧选择），所以"训练时用的是哪一帧"= `frame_0000`。

因此检验结论必须分层：

| 你用的帧 | 性质 | 能说明什么 |
|---|---|---|
| `frame_0000.png` | **就是训练图** | 只能说明"模型记住了这张图"，**不能**当精度证据 |
| `frame_0030 / 0060.png` | 同菜、同场次的其他帧 | 视角/帧级**鲁棒性**检查（菜本身在训练集里）→ 可看"换一帧还稳不稳"，**不等于新数据泛化** |
| 冻结 3262 之外的**新菜**侧视图 | 本地没有 | 这才是有意义的泛化检验；需要新采集（真机内测）或另找数据 |

> 另注：P1-C 的"补 128 盘有没有收益"因此需要重新解读——这 128 行带来的是**视角/域变化**
> （侧拍 1920×1080 视频帧）而非单纯"更多俯拍数据"，重量指标的改善可能部分来自该域差异，报告需写明。

## 3. 怎么自己跑（一条命令）

```powershell
cd C:\Users\user\Desktop\新建文件夹\yitu-zhika-code
# 单张或一次多张（CPU，与在线 /predict 同款管线与精度）
& C:\Users\user\miniconda3\envs\yitu\python.exe scripts/predict_image.py `
    --image "D:/yitu-data/Nutrition5k/side_angle_expansion_v1/dish_1550707995/frame_0000.png" `
    --image "D:/yitu-data/Nutrition5k/side_angle_expansion_v1/dish_1550707995/frame_0030.png" `
    --image "D:/yitu-data/Nutrition5k/side_angle_expansion_v1/dish_1550707995/frame_0060.png"
```
输出：热量/重量/三大宏量/粗类别 + 来源模型（回归=`meal_macros_v1`，类别=`meal_macros_category_v2`）+ 异常字段；
加 `--json` 输出结构化结果。真值可从 `results/side_angle_index.csv` 对应行读取（`gt_calories` / `gt_mass` / …）。

**实测示例**（`dish_1550707995`，真值 116.6 kcal / 107.0 g，类别 vegetable）：

| 帧 | 预测热量 | 预测重量 | 预测类别 |
|---|---|---|---|
| frame_0000（训练帧） | 104.8 kcal | 104.9 g | 蔬菜 98.4% |
| frame_0030 | 103.3 kcal | 94.3 g | 蔬菜 98.8% |
| frame_0060 | 97.0 kcal | 88.7 g | 蔬菜 95.3% |

三帧量级一致 → 可作"同菜换帧稳定性"的直观检查；但因该菜在训练集内，**不能**据此称泛化精度。

## 4. 想要有意义的侧视检验，两条可选路径
1. **留出式重训（推荐，成本中）**：把 128 道侧视菜从训练集剔除后重训五目标模型，
   再在这 128 道菜的 `frame_0030/0060` 上评估 → 得到"侧视视角"的诚实泛化数字（可与"含侧视训练"版本对照）。
2. **真机/新菜采集（成本低但样本少）**：用手机拍同一菜品的侧视与俯视，比较模型输出与自报真值；
   按 `docs/一键内测` 相关清单记录（用户估计/确认/实测分别标记）。
