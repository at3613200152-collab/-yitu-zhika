## 三、汇报口径（诚实表述，务必按此讲）
1. **数据集是本地俯拍子集**（2188/567/507），**不是官方完整多视角 benchmark**；所有指标都注明这点，不与作者论文成绩直接对比。
2. **RGB+NIR 未观察到显著增益**（MAE 差 -0.34 kcal，bootstrap 区间跨 0，MAPE 反而变差）。不要声称"多模态优于 RGB"。
3. **单标签 11 类粗分类**：一张混合餐会被归到最突出的一类，**softmax 会把最高类压到 ~100%、其余 ~0%**，不代表"没有"其它食材；分类头有"偏向蔬菜"问题。界面已注明"非各食材占比、非逐项识别、非识别成功率"。
4. **不宣传"±5%/±15%"等未验证误差**；不用"识别准确率"指代模型置信度（那只是 softmax 分数）。
5. **预测 NIR 是合成的相对强度图**，不是实测光谱；`CalorieCLIP` 是"类外部基线"（复用其公开结构/配置的本地实现），不是作者精确复现。
6. 单种子(42)；预测未钳制（测试集有 4 条负热量，保留原值如实报告）。

## 四、演示应用与工程亮点（超出课设的加分项）
- **信息架构**：微信小程序 **3 个 tab**（今天 / 饮食计划 / 我的）+ 识别确认页；历史经"今天→查看全部历史"。
- **识别与确认**：上传→EXIF剥离→ImageNet ResNet50 食物前置过滤（拦卡通/动漫/截图）→主模型推理→**类别/估算热量/估算份量/多类别置信度**；"确认记录"为主，次之"修改份量/类别/重新选择照片"；明确区分"模型估算 vs 用户填写 vs 待确认"；**未知不填 0**。
- **营养师**：TDEE(Mifflin-St Jeor) + **7 天食谱**（5006 餐盘 + 过敏原过滤 + **中文菜名**：CATEGORY_DISH_NAMES 8 类，按 dish_id 的 MD5 稳定映射）+ 免责声明；支持"预设/商家菜单/自定义食物池"。
- **反馈与采集**：三档反馈 + 手动修正 + quality 分级；按内测方案实现**训练授权默认关**、**原始预测与标签分开存**、**标签分层**（model_only/user_estimate/measured/reference）、**审核状态**、**去标识化 participant_id**（微信登录 openid→伪id）、**图片私有存储**。
- **商家端**：商家上传菜品（含每100g营养）→审核→用户侧"直接看到菜"。
- **微信登录**：`wx.login`→`code2session`→去标识化 participant_id（AppSecret 仅服务器 `.env`）。
- 工程质量：上传10MB、限流30/min、标准化错误JSON、SHA256 校验、前后端链路、API 冒烟13/13。
