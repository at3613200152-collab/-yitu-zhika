- 修复 HSI 与 RGB 的空间错位：原生 HSI 波段需要顺时针旋转 90°，而 RGB 保持不变。只使用 93 个训练扫描选择方向，全部支持同一旋转。旧 v1 数据保留，正式训练使用独立 v2 清单。
- 144 个扫描按拍摄日期分成 93/18/33；859.42 nm 波段使用训练集固定分位数缩放，非逐图缩放。4 层 U-Net 训练 100 轮，最佳第 96 轮，测试 PSNR 23.333 dB、SSIM 0.81198。指标不是完整 HSIFoodIngr-64 数据集成绩。
- Nutrition5k 标签已校验，热量/重量为 kcal/g；冻结俯视图划分为 2188/567/507。RGB 与 RGB＋预测 NIR 的权重、标签、测试行、最佳轮及指标已独立复核。

## 扩容

D:/yitu-data/Nutrition5k/side_angle_expansion_v1 已完成 128 个官方训练餐盘、384 张侧视帧，视频计划总字节 2,421,996,611。其中复用先前 4 餐盘试点，并非额外增加 132 餐盘。所有视频 MD5、PNG 文件/像素 SHA256、标签和训练划分复核通过。与冻结俯视图餐盘 ID 无交集。

11 个视频不足 61 帧，使用真实可解码长度在前 61 帧范围内等距选 3 帧；没有补零或复制帧。128 个餐盘是 128 个样本实体，384 帧不是 384 个独立餐盘。此次扩容未混入已冻结的三模型对照；下一版应按餐盘等权采样，避免多帧使同一标签被过度加权，并保持验证/测试不变。侧视域是否帮助俯视图测试需要单独实验。

## 外部 RGB 基线

新增 src/training/train_calorieclip_official.py，独立实现固定版本公开 CalorieCLIP 的 ViT-B-32 与 MLP 结构，按其配置微调最后两个视觉块，训练 30 轮。只加载通用 OpenAI CLIP 权重，不使用测试集暴露不明的食物微调权重。未公开的 Huber delta、权重衰减、随机种子等采用显式记录的本地配置，不能称为作者训练过程的精确复现。

真实训练图像 CPU 前反向检查确认：通用权重严格加载，最后两层与头部有有限梯度，其余 128 个参数张量保持冻结。初始化日志中的 “No pretrained weights loaded” 来自创建空结构的瞬间；随后有严格的本地 safetensors 加载及 SHA256 门禁，不代表训练使用随机骨干。

实时状态见 results/calorieclip_official_v1/status.json；完成后 scripts/audit_calorieclip_completion.py 检查 30 轮记录、验证集选择、权重、507 个测试标签与指标，并生成 results/experiment_comparison_v1.md。未通过审计时 Demo 不展示外部基线预测。

使用现有 yitu 环境：

```powershell
Set-Location 'C:\Users\user\Desktop\yitu-zhika\yitu-zhika-code'
& 'C:\Users\user\miniconda3\envs\yitu\python.exe' -X utf8 -u app/gradio_demo.py
```
