# 在线主模型切换核对表（label_schema v2 / 12 类）

日期：2026-09-10　用途：把在线 `/predict` 的主模型从当前 `v1_expanded`（11 类）切到
label_schema v2 的 12 类权重（或明确决定不切）时，逐项打勾；**不看评估结果不得切换**。

## 0. 现状（**已完成决策 C：双模型解耦**，2026-09-10）
- 热量/重量/宏量：`checkpoints/meal_macros_v1/v1_expanded/best.pt`（`meal_macros_v1`，`label_schema=v1_11class`）
- 类别：`checkpoints/meal_macros_v1/v3_corrected_seed42/best.pt`（`meal_macros_category_v2`，`label_schema=v2_fruit_12class`）
- 依据：12 类体系让水果可预测（F1 0.837），但同配方热量 MAE 可复现上升（58.31±0.70 → 60.26±0.11，区间不重叠），
  故回归保持最优、类别采用语义修正版；详见 `docs/label_schema_v2_水果类_2026-09-10.md` §6。
- 已完成核对（证据）：
  - `GET /model-info`：`categories` 12 项含 `fruit`(idx 3)、`models.macros.role=primary_regression_macros`、
    `models.category.role=primary_category`、`label_schema=v2_fruit_12class`、`category_manifest` 指向修正清单；
  - `scripts/check_inference_consistency.py`：离线与 HTTP 逐字段一致（含 `category_model`/
    `category_label_schema`/`category_manifest`），`all_pass: true`；热量 231.0 kcal、重量 198.8 g、宏量不变；
  - 小程序：`result.js`/`nutritionist.js` 增加 `fruit`；历史记录按中文名优先 + 按 `category_label_schema`
    选择 11/12 类顺序解释 `category_idx`（已修"旧记录谷物被读成水果"的隐患）；结果页增加解耦说明。
- 回退路径：删除/改名 `CATEGORY_CKPT` 即自动回退为五头权重自带的 11 类类别头（接口字段不缺失）。

## 1. 切换前置条件（决策 C 已满足的部分）
- [x] 12 类模型三种子跑完并与 `v1_expanded` 做**同种子**比较（热量差异超出噪声，已如实记录）
- [x] 五目标指标对比完成；因热量退化，**选择解耦**而非整体切换
- [x] 逐类支持度审计完成（12 类）；`soup_stew/dessert/sauce_condiment` 标注为"不得宣称该类验收"

- [x] 回退方案：保留 `v1_expanded` 权重与 11 类映射，不删除不改名

## 2. 切换步骤（决策 C 的实际做法）
1. **权重指向**：`app/experiment_pipeline.py` 新增 `CATEGORY_VERSION`/`CATEGORY_CKPT`；
   回归仍用 `MACROS_CKPT=v1_expanded`。类别模型按**权重自带 manifest** 解析类别映射
   （`resolve_macros_manifest`，校验 manifest SHA 与 `num_classes`）。
2. **小程序类别展示**：`result.js`/`nutritionist.js` 的 `CATEGORY_IDS`/`CATEGORY_ZH` 增加 `fruit:'水果'`；
   `history.wxml` 为"水果"补色点；结果页新增类别来源说明。
3. **后端类别校验（待办，建议）**：`app/collection.py` 对 `corrected_category` 仍无白名单校验
   （`inference_service.py` 的 record 表默认示例值为 `vegetable`）。建议按当前 `label_schema` 校验并落库
   `label_schema` 字段，避免 11 类与 12 类标注混入同一列无法区分。
4. **重启并核对**：已执行（见 §0 证据）。
5. **记录**：本次切换时间 2026-09-10 13:01（本地），权重 SHA 见 `/model-info` 与一致性证据 JSON。

## 3. 回退步骤
1. `MACROS_CKPT` 改回 `v1_expanded/best.pt`；2. 重启服务；3. 复跑 `check_inference_consistency.py`；
4. 在发布记录中写明回退原因与时间。历史记录中的旧类别名与旧预测**不重写**。

## 4. 禁止事项
- 不得在未完成评估、或仅凭"权重文件存在"的情况下切换。
- 不得把 12 类 logits 用 11 类映射解释（反之亦然）——映射必须来自权重自带清单。
- 不得因为"水果类新增了"就宣称分类整体变准；跨 schema 的 Macro-F1 不可比。
- 不得删除旧权重或旧清单：它们是回退路径与对照基线。
