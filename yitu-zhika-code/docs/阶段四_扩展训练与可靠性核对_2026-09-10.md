### 1.4 加载器的诚实说明（不能宣称"已实现多视角"）

### 1.5 发现的溯源缺口（已在新代码中补上）
`v1_expanded` 的 `best.pt/last.pt` 的 `config` **没有记录 `manifest_sha256` 与 `code_sha256`**
（只有 tag/seed/epochs/batch/protocol），所以"它确实用了扩展清单"当时**无法从权重自证**，
本次是用训练样本数（2316 vs 2188）反推证明的。
新代码起，`config` 记录：`manifest`（路径）+ `manifest_sha256` + `code_sha256` +
`num_classes` + `label_schema_version` + `sampler_seed_base`/`sampler_rule`。

## 2. §6.2 不覆盖的多种子运行与续跑

### 2.1 实测结果（`train_meal_macros.py`）

| 场景 | 命令要点 | 结果 |
|---|---|---|
| 防覆盖 | 对已有非空 tag 直接重跑 | **exit 1**，`[拒绝覆盖] …请使用新的 --tag，或确认要续跑时显式加 --resume` |
| 正常完整跑 | `--tag resumechk --epochs 2 --limit 2` | exit 0，产出 best/last/epochs/test 齐全 |
| 显式续跑 | 同 tag 加 `--resume --epochs 4` | `{"stage":"resumed","next_epoch":3}` → 续跑 epoch 3–4 → exit 0 |
| 中断恢复 | 后台跑到 epoch 3 时**强杀进程** | 目录无 `.tmp` 残留（原子写生效）；`--resume` 从 epoch 4 继续到 6 并完成，exit 0 |
| 数据变化续跑 | `--resume` 但换 manifest | **exit 1**，`[--resume] manifest 已变化，拒绝在旧产物上续跑` |

说明：`best.pt` 只存 `model/epoch/best/best_epoch/config`（保证 `weights_only=True` 可加载，推理/评估侧只读它）；
续跑状态（`optimizer/history/rng`，含 numpy 随机状态）单独存 `last.pt`，`--resume` 显式
`weights_only=False` 读取本地受信文件。开发中一度把 rng 写进 `best.pt`，导致收尾评估
`torch.load(..., weights_only=True)` 抛 `UnpicklingError`，已修复（老产物不受影响）。

### 2.2 修复：采样种子没有使用 `--seed`（真实缺陷）
- 修复前：`DataLoader(generator=torch.Generator().manual_seed(42 + epoch))` —— **硬编码 42**，
  `--seed` 只影响权重初始化与 `seed_epoch` 的全局种子，**多种子的采样顺序完全相同**，种子实验不独立。
- 修复后：`manual_seed(args.seed + epoch)`（与官方脚本 `BASE_SEED+epoch` 口径一致）。
- 兼容性：seed 42 下 `args.seed+epoch == 42+epoch`，与历史 `v1_expanded` **数值行为一致**，
  因此可用 `v2_seed42` 直接做复现性对照；seed 43/44 才是真正独立的采样。
- 初始化种子确实在模型创建前生效：`set_base_seed(args.seed)` 在 `MealMacrosNet(...)` 之前调用。
